# A/B Testing — Measurement Plan

---

## 1. Experiment Design

_Describe the two versions (A and B) and the hypothesis you are testing._

**Your answer:**

Metaprompting is used to improve the bot's initial prompt. The code is modified to handle both versions using the experiments SDK.

Hypothesis: If we apply a metaprompting layer to the bot's initial prompt, then we will reduce the bounce rate of interactions by 10%, because metaprompting optimizes the structure of instructions, reduces hallucinations, and improves the model's adherence to system constraints.

---

## 2. Metrics

_What metrics would you track to compare Version A vs. Version B?_

| Metric | Type | How Measured | Why It Matters |
|--------|------|-------------|----------------|
| Conversational Bounce Rate | | Users who send only one message and leave without receiving a helpful response or further interaction. | Indicate whether the new prompt (metaprompt) is alienating, confusing, or too rigid at first. |
| Goal Completion Rate (GCR) | | Percentage of sessions where the bot reaches a defined "success state" (e.g., booking made, query resolved). | Validates whether prompt optimization actually leads to the resolution of the user's intent. | 
---

## 3. Statistical Methodology

_How would you determine statistical significance? What sample size do you need? How long should the experiment run?_

**Your answer:**

For the bounce rate (a conversion or proportion metric), the standard method is the Z-test for two proportions or the chi-square (χ²) test. Check the Confidence Intervals, If the confidence intervals for Version A and B overlap significantly there is no winner.

The sample size (n) depends on three technical factors:

- Baseline Conversion Rate: must be measured using historical data.

- Minimum Detectable Effect (MDE): The minimum change we want to detect. This must be negociated with the Business team or Stakeholder. The smaller the effect you're looking for, the more users we need.

Statistical Power (1−β): The probability of detecting an effect if it actually exists. The standard is 80%.

How long should the experiment run?

Review the daily usage rate and from there, using the previously calculated sample size n, estimate the number of days.

Along with that, we can use the following heuristics:

- Complete business cycles: Generally 7 or 14 days. This captures the variations in behavior between Mondays (office users) and Sundays (casual users).

- Novelty effect: In the first few days, users may interact more simply because "something changed." Running the test for 2 weeks allows this effect to diminish.

## 4. Guardrails

_What automatic safeguards would stop the experiment if Version B is significantly worse?_

**Your answer:**

An alert could be generated by defining a threshold for the previously measured metrics based on historical data. If the metric exceeds the critical threshold, the experiment can be stopped by calling the Experiments API.
